# Agentic Design Patterns
1. **[Prompt chaining](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/prompt_chaining/promptchaining.md)  :** Prompt chaining follows a divide-and-conquer approach, where a complex problem is broken down into smaller, sequential steps. Instead of asking a single large question to the LLM, the task is split into multiple focused prompts, each executed step-by-step to improve accuracy and control. The output of the previous step becomes input to next step in a sequential manner forming a chain of prompts and hence the name prompt chaining. [Job Matcher](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/prompt_chaining/promptchaining.md) python based code uses langchain and openAI to show how langchain can be used to create prompt chaining where the resume is validated against the job descripton and **gives the matching score, list downs the missing skills and also comes up with high level learning plan with timeline.**
     
   📌 **When to Use This Pattern**  
  Apply this pattern when a problem cannot be effectively solved with a single prompt. It is most useful for workflows that involve multiple stages, require intermediate processing, or depend on interactions with external tools. This approach is especially valuable when building agentic systems that rely on multi-step reasoning and state management.

2. **[Routing](https://github.com/dpgithubRepo/agentic_design_patterns/tree/main/routing):** Routing is an agentic design pattern where an incoming user query is dynamically directed to the most appropriate handler, tool, or agent based on its intent. Instead of processing every request through a single prompt or workflow, the system uses an LLM (or rules) as a decision-maker to classify the input and select the best execution path. This enables specialization, efficiency, and better control over responses. The routing layer acts as a central dispatcher, ensuring that each query is handled by the most suitable component.
In this [routing project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/routing/router.py), a Python-based implementation using OpenAI demonstrates how routing can be used to classify user queries into categories such as code, general, and tool, and delegate them to corresponding agents. For example, coding-related queries are handled by a code agent, general questions by a Q&A agent, and external requests (like weather) by a tool agent. This modular approach improves scalability and makes it easy to extend the system with new capabilities like RAG or finance agents.
     
     📌 **When to Use This Pattern**
     Apply this pattern when your application needs to handle diverse types of user requests that require different processing strategies. Routing is especially useful when a single prompt cannot efficiently or accurately handle all tasks, and specialization is required. It is ideal for systems that integrate multiple tools, APIs, or agents, and where selecting the right execution path is critical. This pattern is widely used in building intelligent assistants, multi-agent systems, and production-grade AI applications that require flexibility, scalability, and maintainability.

3. **[Parallel Processing (Parallel Design Pattern)](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/parallel_pattern/travel_parallel_planer.py)**

     Parallel processing is an agentic design pattern where a task is divided into multiple independent sub-tasks that are executed simultaneously rather than sequentially. Instead of waiting for one step to complete before starting the next (like prompt chaining), multiple prompts or agents run in parallel and their results are later combined to produce the final output. This significantly improves performance, reduces latency, and enables specialized reasoning across different aspects of a problem.
     
     In this [Traveller planner project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/parallel_pattern/travel_parallel_planer.py), a Python-based implementation using LangChain and OpenAI demonstrates this pattern through a travel planning assistant. When a user provides input such as “Plan a 3-day trip to Goa under ₹15,000”, the system does not build the plan step-by-step. Instead, it executes multiple independent tasks in parallel—such as itinerary generation, budget estimation, hotel recommendations, and activity suggestions. Each task processes the same input concurrently, and the outputs are then aggregated into a complete and structured travel plan. LangChain enables this using RunnableParallel, making it easy to orchestrate multiple LLM calls efficiently.

     📌 **When to Use This Pattern** Apply this pattern when a problem can be broken into independent components that do not rely on each other’s outputs. It is especially useful when users expect fast, comprehensive results that combine multiple perspectives at once. In the travel planning use case, itinerary, budget, and recommendations can all be generated independently, making parallel execution ideal. This pattern is highly effective for applications that require multi-dimensional outputs, such as travel assistants, dashboards, recommendation systems, and real-time decision-making tools.
