# Agentic Design Patterns
1. **[Prompt chaining](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/prompt_chaining/promptchaining.md)  :** Prompt chaining follows a divide-and-conquer approach, where a complex problem is broken down into smaller, sequential steps. Instead of asking a single large question to the LLM, the task is split into multiple focused prompts, each executed step-by-step to improve accuracy and control. The output of the previous step becomes input to next step in a sequential manner forming a chain of prompts and hence the name prompt chaining. [Job Matcher](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/prompt_chaining/promptchaining.md) python based code uses langchain and openAI to show how langchain can be used to create prompt chaining where the resume is validated against the job descripton and **gives the matching score, list downs the missing skills and also comes up with high level learning plan with timeline.**
     
   📌 **When to Use This Pattern**  
  Apply this pattern when a problem cannot be effectively solved with a single prompt. It is most useful for workflows that involve multiple stages, require intermediate processing, or depend on interactions with external tools. This approach is especially valuable when building agentic systems that rely on multi-step reasoning and state management.

2. **[Routing](https://github.com/dpgithubRepo/agentic_design_patterns/tree/main/routing):** Routing is an agentic design pattern where an incoming user query is dynamically directed to the most appropriate handler, tool, or agent based on its intent. Instead of processing every request through a single prompt or workflow, the system uses an LLM (or rules) as a decision-maker to classify the input and select the best execution path. This enables specialization, efficiency, and better control over responses. The routing layer acts as a central dispatcher, ensuring that each query is handled by the most suitable component.
In this [routing project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/routing/router.py), a Python-based implementation using OpenAI demonstrates how routing can be used to classify user queries into categories such as code, general, and tool, and delegate them to corresponding agents. For example, coding-related queries are handled by a code agent, general questions by a Q&A agent, and external requests (like weather) by a tool agent. This modular approach improves scalability and makes it easy to extend the system with new capabilities like RAG or finance agents.
     
     📌 **When to Use This Pattern**
     Apply this pattern when your application needs to handle diverse types of user requests that require different processing strategies. Routing is especially useful when a single prompt cannot efficiently or accurately handle all tasks, and specialization is required. It is ideal for systems that integrate multiple tools, APIs, or agents, and where selecting the right execution path is critical. This pattern is widely used in building intelligent assistants, multi-agent systems, and production-grade AI applications that require flexibility, scalability, and maintainability.

3. **[Parallel Processing (Parallel Design Pattern)](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/parallel_pattern/travel_parallel_planer.py)**

     Parallel processing is an agentic design pattern where a task is divided into multiple independent sub-tasks that are executed simultaneously rather than sequentially. Instead of waiting for one step to complete before starting the next (like prompt chaining), multiple prompts or agents run in parallel and their results are later combined to produce the final output. This significantly improves performance, reduces latency, and enables specialized reasoning across different aspects of a problem.
     
     In this [Traveller planner project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/parallel_pattern/travel_parallel_planer.py), a Python-based implementation using LangChain and OpenAI demonstrates this pattern through a travel planning assistant. When a user provides input such as “Plan a 3-day trip to Goa under ₹15,000”, the system does not build the plan step-by-step. Instead, it executes multiple independent tasks in parallel—such as itinerary generation, budget estimation, hotel recommendations, and activity suggestions. Each task processes the same input concurrently, and the outputs are then aggregated into a complete and structured travel plan. LangChain enables this using RunnableParallel, making it easy to orchestrate multiple LLM calls efficiently.

     📌 **When to Use This Pattern** Apply this pattern when a problem can be broken into independent components that do not rely on each other’s outputs. It is especially useful when users expect fast, comprehensive results that combine multiple perspectives at once. In the travel planning use case, itinerary, budget, and recommendations can all be generated independently, making parallel execution ideal. This pattern is highly effective for applications that require multi-dimensional outputs, such as travel assistants, dashboards, recommendation systems, and real-time decision-making tools.

   
4. **[Tool Use Pattern](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/tool_use_pattern/tool_use.py)** :
Tool use is an agentic design pattern where an LLM is enabled to interact with external functions, APIs, or systems to perform tasks beyond its internal knowledge. Instead of relying solely on generated responses, the model can decide when to call a tool, pass the required inputs, and use the returned results to generate a more accurate and actionable response. This transforms the LLM from a passive responder into an active decision-making agent that can fetch real-time data, execute operations, and integrate external information into its outputs.

     In this [project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/tool_use_pattern/tool_use.py), a Python-based implementation using OpenAI demonstrates how tool use can be applied to build a stock price assistant. When a user provides a query such as “What is the price of RELIANCE.NS?”, the model analyzes the intent and determines that real-time data is required. It then invokes a tool function (get_stock_price) which fetches the latest stock price using yfinance. The result is passed back to the model, which incorporates it into a natural language response. This approach ensures that responses are grounded in live data rather than static knowledge, improving reliability and usefulness.
     
     📌 **When to Use This Pattern**
     Apply this pattern when your application requires real-time data, external system interaction, or execution of specific actions that cannot be handled by the LLM alone. It is especially useful for scenarios such as fetching live information (stock prices, weather), querying databases, performing calculations, or triggering workflows. Tool use is essential when accuracy depends on external sources and when building systems that need to move beyond conversation into action-oriented intelligence.

5. **[Planning Pattern](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/planning_pattern/planning_agent.py)** :
Planning is an agentic design pattern where a complex problem is first decomposed into a structured sequence of steps before execution begins. Instead of directly asking the LLM to generate a final answer, the model is prompted to create a plan that outlines how the task should be solved. Each step in the plan is then executed sequentially, ensuring better reasoning, clarity, and control over the process. This separation of planning and execution allows the system to handle complex tasks more reliably and transparently.

     In this [project](https://github.com/dpgithubRepo/agentic_design_patterns/blob/main/planning_pattern/planning_agent.py), a Python-based implementation using LangChain and OpenAI demonstrates how the planning pattern can be used to build a step-by-step reasoning agent. When a user provides a task such as “Analyze whether investing in Reliance is a good idea”, the system first generates a plan—like gathering company information, analyzing financials, evaluating risks, and providing a recommendation. Each of these steps is then executed individually using an executor chain, and the results are combined into a final structured response. This approach improves the quality of outputs by ensuring that the problem is solved in a logical and organized manner.
          
     📌 **When to Use This Pattern**
          Apply this pattern when a problem requires multi-step reasoning, structured execution, or decision-making where order matters. It is especially useful for complex workflows such as financial analysis, research tasks, strategic planning, and task automation. This pattern is ideal when a single prompt is insufficient to produce accurate results and when breaking the task into smaller steps leads to better clarity, control, and reliability.

     **[6.Multi-Agent Collaboration Pattern](https://github.com/dpgithubRepo/agentic/blob/main/web_summarizer/README.md)** :
     Multi-agent is an agentic design pattern where a complex task is handled by multiple specialized agents working collaboratively, instead of a single LLM handling everything. Each agent is assigned a specific role or responsibility, such as research, analysis, summarization, or validation. These agents can operate sequentially, in parallel, or in coordinated workflows, and their outputs are combined to produce a final result. This approach improves scalability, modularity, and overall performance by leveraging division of responsibilities and specialization.
     
     In this [project](https://github.com/dpgithubRepo/agentic/blob/main/web_summarizer/README.md), a Python-based implementation using Crewai demonstrates the multi-agent pattern through an interactive dashboard for web topic summarization. When a user provides a topic, multiple agents are triggered to perform different parts of the workflow—such as gathering information, processing content, and generating summaries. The system streams real-time updates showing the status of each agent (pending, working, completed), along with a live timer that tracks execution progress. The results are dynamically updated in a visually rich Gradio interface, giving users full visibility into how agents collaborate to produce the final summary. This design highlights how multi-agent systems can provide both transparency and efficiency in AI workflows.

     📌 **When to Use This Pattern**
        Apply this pattern when a problem can benefit from multiple specialized agents working together, especially in workflows that involve distinct responsibilities such as data collection, processing, analysis, and presentation. It is particularly useful for building complex AI systems like research assistants, content generation pipelines, dashboards, and enterprise automation tools. This pattern is ideal when scalability, modularity, and real-time visibility into task execution are important, and when a single-agent approach is insufficient to handle the complexity of the task effectively.
